# 店小助：从店铺接待中延伸出的客服工具

做商城时，买家会反复问价格、怎么使用、什么时候发货；退款和投诉又需要店主自己核实。店小助把客服接待单独做成一个工具：**先用默认回复，需要时再按商品定制。**

[打开店小助项目](https://github.com/yelinyuan798-commits/UniversalECommerceBot) · [安装和使用说明](https://github.com/yelinyuan798-commits/UniversalECommerceBot/blob/main/docs/PLATFORM_SETUP.md) · [测试记录](https://github.com/yelinyuan798-commits/UniversalECommerceBot/blob/main/docs/TEST_REPORT.md)

## 先用默认的，再按商品调整

| 用法 | 需要准备什么 | 能做什么 |
| --- | --- | --- |
| 直接用默认客服 | 不用先填商品资料，也不用 AI 密钥 | 回复问候，询价、库存和发货问题引导查看商品或订单页面；需要核实的细节和售后记入人工待办 |
| 按商品定制 | 填写商品介绍、价格、最低报价、发货说明和常见问答 | 按已填资料回答具体商品问题，支持按底价议价或单独设置不议价 |

默认客服不会读取商品页面来获取实时价格、库存或订单状态。填了商品资料以后，也需要切换到“按商品定制”才会用这些资料回答。切换模式会保留已有商品设置。

人工待办显示在店小助的本地工作台中，对应会话会暂停自动回复，处理后可恢复。它不代表平台已分配另一位客服，也不会自动向店主发送外部通知。

## AI 在工作台里设置

不接 AI，两种用法都可以运行。想让默认客服表达更自然时，在工作台打开 **“AI 设置”**：

1. 填入服务商提供的接口地址、模型名称和 API 密钥。
2. 点击 **“测试连接”**，检查当前填写的信息是否可用。测试只发一条测试消息，不发买家资料，也不会保存设置或开启 AI。
3. 按需要启用 AI，点击 **“保存设置”**。之后在右侧试聊，查看实际回复；配置状态与连接测试结果分开显示。

密钥保存在自己电脑上，不会在页面中回显，也不要放进商品问答或公开仓库。模型服务可能计费。默认模式调用 AI 时，只发送本次买家提问和通用接待规则，不发送保留的商品资料或旧会话；商品定制模式会发送识别问题所需的相关资料。

AI 用于改善普通接待的表达，不能替店主决定优惠、商品事实或售后结果。连接失败或回复未通过检查时，会使用内置话术；退款、投诉等需要人工处理的消息仍按接管规则处理。具体设置以[店小助使用说明](https://github.com/yelinyuan798-commits/UniversalECommerceBot/blob/main/docs/PLATFORM_SETUP.md#可选让默认客服说得更自然)为准。

## 连接店铺前，先自己试聊

安装后可以先在本机问“在吗”“多少钱”“我要退款”，检查默认接待和人工暂停。需要具体报价时，再添加自己的商品，并用模拟咨询核对回复。

连接真实店铺仍需商家账号及平台设置。网页平台需要按当前客服页面配置消息识别与发送位置；先观察新消息，再开启发送，并用测试买家确认实际收件。当前接入通过电脑上的网页工作台或消息协议完成，不是直接控制手机 App。

| 平台 | 已有验证依据 |
| --- | --- |
| 闲鱼、淘宝 / 千牛、京东 / 咚咚 | 项目作者于 2026-11-03 反馈已完成真实店铺消息收发测试 |
| 拼多多、抖店、快手小店、小红书 / 千帆 | 已有适配代码和本地浏览器集成测试，待真实店铺验证 |

这里沿用客服项目作者反馈，未因编写本补充而独立重做实店测试。不同店铺和页面版本仍要分别配置、验收，最新情况见客服项目的测试记录。

## 与本商城的关系

本仓库保存的是 Dujiao-Next 商城改造与经营经历；店小助是单独安装、单独配置的客服项目。本次补充只提供介绍和使用入口，没有连接两者的数据或业务接口。

例如，买家问商品如何使用，可以由已配置的商品问答回复；买家说“已付款”或要求退款，需要店主在原商城或平台核实。聊天内容不会触发本商城的付款确认、卡密发放、订阅开通、退款或订单改价，也没有完成这类履约集成。

两个项目的源码与配置分别维护。需要使用客服功能时，请到店小助仓库安装和更新；本仓库的历史经营记录、商城功能与部署方式保持原有含义。
